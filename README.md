# 智能运营决策分析平台

面向用户行为序列分析、RFM分层、流失预警、智能推荐、归因建模、活动效果评估与实时运营决策的数据分析工程平台。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面（就地维护，使用 <模块>/index.tsx）
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

### 归因发布前复算

归因模型发布前必须先完成触点贡献复算，模型状态与复算结果一起提交：

1. 复算只按新字段范围读取模型配置：`目标指标`、`触点权重配置`、`贡献率下限`、
   `贡献率上限`、`数据窗口开始`、`数据窗口结束`；展示字段「触点权重分布」不参与计算。
2. 触点贡献值 = 触点权重 × 数据窗口内的触点转化值（取自目标指标事件记录），
   贡献占比 = 触点贡献值 / 合计；明细表与核对表都保留来源映射。
3. 权重合计不为 1、事件窗口无数据、贡献占比越过上下限时，复算被标记为「越界阻断」，
   不能落定、不能登记为指标结论，模型也不能发布（状态保持不变）。
4. 落定的核对表登记到「指标下钻待处理明细」；并发核对只采信已落定核对表。
5. 同一目标指标只引用一个归因版本，多个已评审版本需在归因建模页显式「切换指标引用」；
   已确认/已归档的指标归因按原模型快照只读查看，不随版本变化。
6. 模型生命周期：草稿 → 模型评审中 → 已评审 → 已发布 → 已下线 → 已归档，
   支持恢复；切换、归档、恢复均写入变更留痕。

METR-0002 作为回归样例：支付转化率下降分析初始引用已发布的 ATTR-0001 V1，同一指标下
还有 ATTR-0004/ATTR-0005（V2）与 ATTR-0006（V3）三个已评审候选；ATTR-0006 贡献率越界，
发布会被阻断；ATTR-0004/0005 发布后需显式切换引用，切换后贡献度排名与根因随之变化。
本地演示或回归重跑可调用 `POST /api/admin/reset` 把示例数据恢复初始状态。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.tsx`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
